
# 全流程操作手册（必读）

本文档是各阶段的可执行操作说明，按顺序执行。每阶段末尾标注输出产物与进入下一阶段的门槛。

## Phase 0 · 环境初始化

目标：建立本书文件系统记忆与状态库。

步骤：
1. 在 skill workspace 下新建 `<书目录>/`，命名规则 `book_<拼音或英文短名>`。
2. 创建 `chapters/`、`memory/`、`reviews/` 三个子目录。
3. 创建 `state.json`（骨架见 SKILL.md），`draft_mode` 置 `true`。
4. 若之前有旧书文件（docx/txt/md），先全量扫描 AIGC 痕迹再入库（见 deai-scan.md）。

产物：书目录 + state.json。
门槛：目录结构完整，state.json 可被脚本读取。

## Phase 1 · 扫榜选题（可选）

用户需要"写什么"时执行；已有明确题材可跳过。

1. 目标平台：番茄小说、七猫免费小说、起点中文网（男频/女频按用户倾向）。
2. 抓取方式：宿主环境支持浏览器时直接访问榜单页；否则用搜索工具检索"番茄小说 榜单 2026 都市""七猫 玄幻 热度榜"等关键词，记录书名、题材、简介、开篇钩子。
3. 产出：`memory/benchmark.md`——榜单 TOP 10 列表，标注题材分布、重复题材、空白题材。
4. 选题材：与用户讨论 3 个候选，结合空白题材与用户擅长领域定 1 个。

产物：benchmark.md。
门槛：题材已定，进入 Phase 3 做三层问答。

## Phase 2 · 爆款拆文（可选）

用户提供对标书（书名或前几章文本）时执行。

1. 获取对标书前 3 章文本（用户提供或公开片段）。
2. 拆解维度：
   - 开篇三要素：主角处境、第一个冲突、悬念钩子出现位置。
   - 节奏表：每 500 字情绪高点/低点分布，冲突密度。
   - 钩子类型：信息差钩子、危机钩子、身份钩子、奖励钩子。
   - 爽点结构：金手指释放节奏、打脸/逆袭/收服的轮换。
3. 产出：`memory/breakdown_<对标书>.md`，含"节奏模板"与"钩子清单"，供 Phase 4 大纲套用。

产物：breakdown 文件。
门槛：无（拆文产物仅为参考模板，不强制）。

## Phase 3 · 三层问答初始化（强制）

通用网文核心步骤，每本新书必做。详细规则见 `setup-planning.md`。

1. 第一层·世界观：题材背景、力量体系/规则、核心冲突舞台。
2. 第二层·人物：主角动机、主角缺陷、关键配角与反派、人物关系网。
3. 第三层·冲突：主线冲突、中期危机、开篇三章的具体冲突设计。

每层至少 5 问 5 答，答案写入 `book.md`。回答不足时继续追问，禁止自行脑补用户未确认的设定。

产物：book.md。
门槛：三层问答完成，book.md 含世界观/人物/冲突三节，用户确认无遗漏。

## Phase 4 · 大纲规划

1. 全书大纲：主线走向（起承转合）、预计总字数、卷划分。
2. 卷纲：每卷目标、起止章节、卷内高潮点。
3. 前三章细纲：每章场景、冲突、结尾钩子（钩子必须落到 `memory/plot_threads.md` 台账）。
4. 伏笔备案：每条伏笔记录"埋设章节 → 预计兑现章节 → 状态"。

产物：outline.md + plot_threads.md 初始台账。
门槛：大纲用户确认，伏笔台账非空。

## Phase 5 · 分章写作

1. 每次写一章（或用户指定批量），输出到 `chapters/ch_XXX.md`。
2. 遵循写作守则（writing-consistency.md），单章 1500-3000 字（网文常见节奏）。
3. 章末必须留钩子；若为卷末章可留"大钩子"。
4. 写完后更新 state.json 的 current_chapter，并同步 plot_threads.md（新埋设/已兑现）。

产物：章节文件 + state.json 更新。
门槛：章节落盘，状态库同步。

## Phase 6 · 去AI味

对初稿逐段执行 deai_rules.py 命中检测并改写。详细规则见 `deai-scan.md`。

1. 运行 `python scripts/deai_rules.py <章节文件>` 得到命中清单。
2. 逐段改写：消除AI腔、化抽象为具象、制造个人化表达。
3. 改写后再跑一次，直到命中数归零或用户认可剩余项。

产物：去AI味后的章节。
门槛：AI腔命中项处理完毕。

## Phase 7 · 多视角审稿

三个视角轮换审稿，记录到 `reviews/review_<章节>.md`：

1. 编辑视角：节奏是否拖沓、钩子是否断、情绪密度是否达标。
2. 读者视角：代入感、是否想继续读、是否有"毒点"。
3. 数据视角：本章字数、钩子强度、伏笔推进是否符合大纲节奏。

每个视角列出 Top 3 问题与修改建议；用户确认后重写。详细见 `review-validation.md`。

产物：review 文件 + 重写章节。
门槛：三视角问题处理完。

## Phase 8 · 自动校验（强制门禁）

1. 字数检查：`python scripts/wordcount_check.py <章节>`。
2. 一致性检查：`python scripts/check_consistency.py <书目录>`（伏笔状态、人物设定冲突）。
3. AIGC 扫描：`python scripts/scan_ai_traces.py <书目录或文件>`，支持 txt/md/docx。
4. 三项全部通过才可交付；docx 转换后必须重扫。

产物：校验报告（stdout 或写入 reviews/check_report.txt）。
门槛：三项零报错；AIGC 痕迹 0 残留。

## 交付守则

- 对外复制、上传、导出任何章节/全文前，重跑 scan_ai_traces.py。
- 每次交付说明"校验结论 + 残留数"，不得只口头保证。
