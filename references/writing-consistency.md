
# 写作守则与一致性追踪

来源：整合 webnovel-writer 的状态库 RAG 伏笔追踪 + Oh Story 文件系统记忆。

## 一、单章写作守则（通用网文）

### 篇幅与结构

- 单章推荐 1500-3000 字（番茄/七猫常见节奏；起点可放宽至 2500-4000）。
- 章节结构：场景进入（≤300字）→ 事件推进（主体）→ 章末钩子（最后 50-100 字）。
- 每章至少推进一条剧情线：主线推进 / 支线推进 / 人物成长 / 伏笔新信息，四选一或以上。

### 行文要求

1. 开头别堆设定：环境描写让位于动作与对话。
2. 对话带信息：世界观交代优先通过人物对话与行动展现，禁止大段旁白设定。
3. 冲突具体化：不说"他很生气"，写"他攥紧的拳头把茶杯捏出裂纹"。
4. 情绪密度：每章至少一个情绪高点（爽/燃/虐/悬）。
5. 少用副词堆叠：避免"缓缓地""静静地""轻轻地"连发。
6. 视角一致：单章内视角人物不随意切换，切换需空行分隔。
7. 禁止注水：重复解释同一设定、无信息量的心理独白不超过 100 字。

### 钩子纪律

- 每章末尾必须有钩子（悬念/危机/奖励/信息差四类轮换）。
- 卷末章允许"大钩子"（局势反转、身份揭晓、强敌压境）。
- 钩子内容写入 `memory/plot_threads.md` 台账，编号 T01 起。

## 二、状态库机制（webnovel-writer 机制）

### state.json 更新时机

| 时机 | 更新内容 |
|------|----------|
| 完成一章写作 | current_chapter + 1；draft_mode 保持 true |
| 去AI味完成 | 无结构变化 |
| 审稿重写完成 | draft_mode 置 false（本章定稿） |
| 新伏笔埋设 | open_threads 增加条目 |
| 伏笔兑现 | open_threads 移除对应条目，台账状态改"已兑现" |

### 写作前必查

动笔写第 N 章前，先读：
1. `memory/plot_threads.md` —— 近期该推进/兑现哪些伏笔。
2. `memory/characters.md` —— 出场人物的动机与关系是否一致。
3. 前三章或上一章结尾 —— 承上启下，不接错钩子。

### RAG 式检索（轻量版）

写作中涉及旧设定时，按"关键词 → memory 文件 → 相关段落"检索确认，禁止凭印象写。印象与档案冲突时，以档案为准并提示用户修正档案或修改文本。

## 三、一致性追踪检查点

每写完 5 章或用户要求时，运行 `check_consistency.py`，检查：

1. **伏笔状态**：台账中"已埋设"超过 20 章未推进 → 警告；超过 50 章 → 报错（烂尾风险）。
2. **人物设定冲突**：人物名、身份、能力数值与 characters.md 档案不一致 → 报错。
3. **地名/组织名冲突**：世界设定中的专名拼写不一致 → 报错。
4. **章节链接**：ch_001 后缺失 ch_002 → 报错；章节文件名不连续 → 警告。
5. **金手指限制**：金手指能力超出档案登记的触发条件/限制 → 报错（战力崩坏预警）。

## 四、常见崩坏模式与预防

| 崩坏模式 | 预防方法 |
|----------|----------|
| 战力崩坏 | 力量体系等级表写进 world.md，升级必须消耗资源或经历事件 |
| 伏笔烂尾 | 台账每周/每 10 章复盘一次，未推进的伏笔标记并处理 |
| 人设漂移 | 主角决策前对照"动机"条目：这个选择符合他的核心欲望吗 |
| 时间线混乱 | book.md 中记录关键时间节点，涉及时间跳跃时更新 |
