
# 审稿视角与自动校验标准

来源：整合 InkOS 的多 Agent 审计思想 + Chinese Novelist 的自动校验 + Oh Story 确定性门禁。

## 一、三视角审稿（Phase 7）

对每一章（或用户指定范围）轮换三个视角审稿，每视角输出 Top 3 问题。

### 1. 编辑视角（结构/节奏）

检查项：
- 开头 300 字是否抓住人（场景进入是否太快/太慢）
- 章末钩子是否成立（是否只是"本章结束"而非"下一章悬念"）
- 冲突密度：是否有连续 500 字无冲突无信息量的段落
- 节奏曲线：本章情绪高点位置是否合理（前段/中段/后段）
- 信息量：新设定/新人物是否一次性堆太多

### 2. 读者视角（体验/代入）

检查项：
- 代入感：主角视角是否清晰，读者能否"跟着主角走"
- 毒点排查：圣母/降智/双标/强行巧合/金手指滥用
- 对话可信度：人物说话是否符合身份性格
- 章节阅读体验：是否想继续读下一章（不想，说明钩子失败）

### 3. 数据视角（可量化校验）

检查项：
- 字数是否在目标区间
- 钩子类型是否与台账登记一致
- 本章推进的剧情线是否符合大纲计划
- 伏笔埋设/兑现是否符合台账时间表

### 审稿记录模板（reviews/review_<章节>.md）

```markdown
# <章节> 审稿记录 <日期>
## 编辑视角
1. ...
2. ...
3. ...
## 读者视角
1. ...
2. ...
3. ...
## 数据视角
- 字数：xxx（目标 1500-3000）
- 钩子：xxx（台账登记 xxx）
- 剧情线推进：xxx
## 修改清单
- [ ] 问题1 → 修改方案
- [ ] 问题2 → 修改方案
```

## 二、自动校验（Phase 8 强制门禁）

### 校验项与脚本

| 检查项 | 脚本 | 通过标准 |
|--------|------|----------|
| 字数与断章钩子 | wordcount_check.py | 字数在区间；每章末有钩子特征 |
| 伏笔/设定一致性 | check_consistency.py | 0 错误；警告数用户确认 |
| AIGC 痕迹 | scan_ai_traces.py | 0 残留 |
| 章节连续性 | check_consistency.py | 章节号连续无缺 |

### 门禁流程

1. 全部脚本顺序执行。
2. 任一脚本报错（error 级）→ 停止交付，修复后重跑。
3. 警告（warning 级）→ 列出清单，用户逐项确认或修复。
4. 全绿 → 生成 `reviews/check_report.txt` 校验报告，写明日期、范围、各项结论。

### 校验报告模板

```text
校验报告 <日期>
范围：<书目录>/<章节范围>
[1] 字数检查：通过 / 失败（详情）
[2] 一致性检查：0 错误，N 警告
[3] AIGC 痕迹扫描：0 残留
结论：可交付 / 不可交付
```

## 三、重写策略

- 审稿问题修复采用"先改大纲问题 → 再改段落问题 → 最后润色"的顺序。
- 单次重写只处理 Top 问题，不整章推翻（除非用户要求）。
- 重写后必须回到 Phase 8 重新校验（AIGC 重扫是硬性要求，重写可能回写痕迹）。
